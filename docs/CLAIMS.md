# Claims and how to check each one

Every claim sentence in the README ends with a tag such as `[C1a]` that names a row of this table. A row gives the claim, where the evidence sits, one command and one expected substring of its output. The lint (`scripts/claims-lint.ts`) resolves every tag against these rows, and `scripts/claims-run.sh` runs the commands.

- Ids are `C<n>` or `C<n><letter>`, for example `C1a`.
- The Command cell is one command in one pair of backticks. A pipe inside a cell is written `\|`; the lint and the runner unescape it.
- Expected output is one backticked substring that must appear in the output of the command.
- Needs is `none` (Node 24 and pnpm only, counts as `node`), `network` (RPC reads, no keys), `keys`, or a comma separated list of the tools the command uses: `node`, `rust`, `kani`, `lean`. `scripts/claims-run.sh --tier node|rust|full` prints `SKIP <id> needs <tool>` for a row whose tool is missing instead of a failure.
- Pending marker: inside the backticks a Command cell may start with `pending: AIR-<nnn>` (the ticket whose output the command needs), followed by the command to run once that ticket lands, for example `scripts/bench-replay-check.sh`. The lint and the runner strip the backticks before they read the marker, treat such a row as pending and never run it. AIR-255 deletes the `pending: AIR-<nnn> ` prefix, and the lint run with `--final` fails while any row is still pending. A cell that holds only `pending: AIR-240` is a placeholder until AIR-240 writes the row.
